## 一、项目概述

**项目名称**：ecom-image-studio

**项目目标**：构建一个前后端分离的电商图片批量处理工作台，实现两条核心工作流：

**工作流 A：5 张参考图 → 5 张成品图**
输入 5 张不同的参考底图，通过 `gpt-image-2.5` 图像编辑模型，输出 5 张保留原图构图但替换了文字、Logo、局部内容、主体或背景的自有成品图。每张参考图独立生成一张对应成品图，5 张图之间不需要保持一致，但支持统一的编辑规则。

**工作流 B：5 张成品图 → 1 张电商长图**
将工作流 A 的输出按指定顺序纵向拼接为一张电商详情页长图，支持图片间距、背景色、顶部/底部留白、输出宽度等参数配置。

**关键约束**：所有编辑必须支持"精确到单个文字块/Logo 块"的粒度的控制。一张图可能检测到 1~10 处文字，每处必须能被用户独立识别、独立配置、独立编辑。

## 三、核心概念与数据模型

### 3.1 核心概念

| 概念 | 说明 |
|------|------|
| Source | 用户上传的参考底图 |
| Output | 编辑后的成品图 |
| Composite | 拼接后的长图 |
| TextBlock | 一张图上检测到的一处文字，有唯一 ID |
| LogoBlock | 一张图上检测到的一处 Logo，有唯一 ID |
| Mask | 编辑时传给模型的 PNG，透明区域=要重绘，不透明区域=保留 |
| EditStep | 一次编辑操作（背景/颜色/灯泡/文字/Logo） |
| Task | 一次批量任务（5 张图 × N 步） |
| Job | 单个图单个步骤的子任务 |

### 3.2 核心原则

**一处文字 = 一个唯一 ID = 一个独立 mask = 一次独立编辑。**

用户看的是编号和缩略图，模型看的是 mask 和位置描述，两边通过 ID 对齐。

### 3.3 数据模型

```python
class TextBlock(BaseModel):
    id: str              # "T1", "T2", ...
    bbox: tuple[int,int,int,int]   # x1, y1, x2, y2
    position: str        # "top-left", "center", ...
    original: str        # OCR 原文
    replace: str         # 用户填的新文案，为空表示不改
    enabled: bool = True
    mask_path: str | None = None

class LogoBlock(BaseModel):
    id: str              # "L1", "L2", ...
    bbox: tuple[int,int,int,int]
    position: str
    detected: bool = True
    replace_with: str | None = None  # 自有 logo 文件 id
    enabled: bool = True
    mask_path: str | None = None

class SourceImage(BaseModel):
    id: str
    filename: str
    path: str
    width: int
    height: int
    text_blocks: list[TextBlock] = []
    logo_blocks: list[LogoBlock] = []

class EditRule(BaseModel):
    text_replace_enabled: bool = True
    logo_replace_enabled: bool = True
    background_replace_enabled: bool = False
    background_prompt: str = ""
    shade_color_enabled: bool = False
    shade_color: str = ""
    bulb_replace_enabled: bool = False
    bulb_prompt: str = ""
    quality: str = "high"
    size: str = "1024x1024"
    strategy: str = "serial"  # "serial" | "merged"

class BatchTask(BaseModel):
    id: str
    created_at: datetime
    source_ids: list[str]
    edit_rule: EditRule
    status: str          # queued / running / completed / partial_failed / failed
    jobs: list["Job"] = []

class Job(BaseModel):
    id: str
    source_id: str
    step: str            # "background" | "shade" | "bulb" | "text_T1" | "logo_L1"
    target_id: str | None = None   # 文字块 ID 或 Logo 块 ID
    status: str          # pending / processing / done / failed
    prompt: str = ""
    mask_path: str | None = None
    input_path: str = ""
    output_path: str = ""
    error: str | None = None
    retry_count: int = 0
```

## 四、gpt-image-2.5 API 规格

### 4.1 模型选择

- 编辑用 `gpt-image-2.5-sunburst`（精度优先，适合电商产品图）
- 草稿用 `gpt-image-2.5-flare`（速度优先，仅在快速试稿时使用）

### 4.2 编辑接口

`POST /v1/images/edits`，`multipart/form-data` 格式。

**请求参数**：

| 参数 | 类型 | 说明 |
|------|------|------|
| model | string | "gpt-image-2.5-sunburst" |
| image | file | 参考图，PNG/WebP/JPG，<50MB，最多 16 张 |
| mask | file | 可选，PNG 带 alpha 通道，尺寸与第一张输入图一致，透明区域=要重绘 |
| prompt | string | 编辑指令，最长 32000 字符 |
| size | string | "1024x1024" \| "1536x1024" \| "1024x1536" \| "auto" |
| quality | string | "low" \| "medium" \| "high" \| "xhigh" \| "max" \| "auto" |
| output_format | string | "png" \| "jpeg" \| "webp" |
| n | int | 1-10 |

**Python 调用示例**：

```python
import openai, base64

client = openai.OpenAI()

result = client.images.edit(
    model="gpt-image-2.5-sunburst",
    image=open("source/ref_01.png", "rb"),
    mask=open("masks/ref_01_T1_mask.png", "rb"),
    prompt="Replace the text ...",
    size="1024x1024",
    quality="high",
    output_format="png",
)

img_bytes = base64.b64decode(result.data[0].b64_json)
```

**重要约束**：

- mask 透明区域将被重绘，不透明区域保持原样
- 如果省略 mask，模型自行决定修改区域
- 每张图独立调用，不要尝试一次调用处理多张图
- 并发数不超过 3
- 每次编辑调用必须保存完整输入快照（原图哈希、prompt、mask 路径、模型参数）

## 五、多文字块处理机制（核心章节）

### 5.1 问题描述

一张电商图可能检测到 3 处、5 处甚至 8 处文字。必须让用户知道"我改的是哪一处"，也必须让模型知道"它要改哪一处"。

### 5.2 用户侧：如何让用户知道改的是哪一处

**第一，OCR 跑完后，前端在原图上叠加编号标注框。**

每检测到一个文字块，就在原图上画一个半透明矩形，左上角标 `T1`、`T2`……`T8`。用户一眼就能看到每处文字的编号和位置。

**第二，右侧提供可编辑表格。**

| ID | 位置 | 原文 | 替换为 | 启用 |
|----|------|------|--------|------|
| T1 | 左上角 | 限时特价 | LUMOS 新品首发 | ✓ |
| T2 | 顶部居中 | 爆款直降 | 限时 8 折 | ✓ |
| T3 | 右上角 | 今日秒杀 | 新品上市 | ✓ |
| ... | ... | ... | ... | ... |
| T8 | 右下角 | 立即抢购 | 立即购买 | ✓ |

**第三，双向联动。**

- 鼠标悬停表格某一行 → 原图上对应标注框高亮
- 点击原图上某个框 → 表格自动滚动到对应行

**第四，批量操作模式。**

- **统一文案模式**：用户只填一句，所有勾选的文字块都用它
- **按原文分组**：OCR 出现多次的原文自动分组，填一次同组全部应用
- **逐条编辑**：每处单独填
- **自动跳过**：原文与新文一致，或未勾选的块，不调用 API

### 5.3 模型侧：如何让模型知道改的是哪一处

每次调用 gpt-image-2.5 时，必须做到三重锚定：

**第一重：mask 是决定性的。**

8 处文字就生成 8 个独立 mask，每次编辑只传当前这一处的 mask。mask 的透明区域精确覆盖目标文字块，模型在像素级就知道"只能改这里"。

**第二重：prompt 里写位置描述。**

位置用自然语言九宫格表示。从 bounding box 中心坐标归一化到 0-1，映射到：

```
top-left, top-center, top-right,
middle-left, center, middle-right,
bottom-left, bottom-center, bottom-right
```

如果有语义位置（"产品下方"、"图片底部"），也可以用 `below the product`、`at the bottom of the image`。

**第三重：prompt 里引用原文。**

写 `Replace the text "今日秒杀"` 而不是 `Replace the text in this area`。原文帮模型确认 mask 区域里确实写着这几个字。

### 5.4 重复原文的处理

假设一张图里有两处都写"限时特价"，检测出 `T2` 和 `T6`。

- **想让两处改成同一句**：合并 mask，prompt 写 `Replace all instances of the text "限时特价" with "LUMOS 新品首发"`
- **想让两处改成不同句**：分开跑两次，每次只传一个 mask，prompt 里加位置区分：`Replace the text "限时特价" in the top-left corner...` 和 `Replace the text "限时特价" in the bottom-right corner...`

**默认策略**：分开跑，可控性更高。

### 5.5 完整示例（8 处文字）

```yaml
source: ref_03.jpg
text_blocks:
  - {id: T1, bbox: [80, 60, 320, 120],   position: top-left,      original: 限时特价,      replace: LUMOS 新品首发}
  - {id: T2, bbox: [420, 60, 620, 120],  position: top-right,     original: 今日秒杀,      replace: 新品上市}
  - {id: T3, bbox: [250, 400, 550, 460], position: center,        original: 三档调光,      replace: 五档调光}
  - {id: T4, bbox: [250, 500, 550, 560], position: center,        original: 护眼无频闪,    replace: 全光谱护眼}
  - {id: T5, bbox: [250, 600, 550, 660], position: bottom-center, original: 包邮到家,      replace: 顺丰包邮}
  - {id: T6, bbox: [80, 720, 320, 780],  position: bottom-left,   original: 7 天无理由,    replace: 30 天无理由}
  - {id: T7, bbox: [420, 720, 620, 780], position: bottom-right,  original: 立即抢购,      replace: 立即购买}
  - {id: T8, bbox: [300, 850, 500, 900], position: bottom-center, original: LUMOS 官方旗舰店, replace: LUMOS 官方旗舰店}
```

`T8` 原文与新文一致，后端跳过不调用 API。其余 7 处，每处生成独立 mask，串行调用 7 次。

## 六、五种编辑类型的 Prompt 模板

**通用公式**：`[具体改动指令] + [必须保留的锁定清单] + [输出格式约束]`

### 6.1 背景更换

**输入**：原图 + mask（透明区域=原背景）
**Prompt**：

```text
Replace only the background with {background_description}. 
Keep the {subject} completely unchanged — its shape, proportions, color, 
material, metal finish, cable, contact shadows, and all existing text and logo. 
Preserve the original composition, camera angle, and product position. 
Do not alter any part of the {subject}. 
Output a photorealistic e-commerce product image.
```

### 6.2 主体局部换色（如灯罩）

**输入**：原图 + mask（透明区域=灯罩区域）
**Prompt**：

```text
Change only the lampshade color to {color}. 
Keep the lampshade's shape, material texture, seams, stitching, metal frame, 
bulb, cable, background, and all text and logo exactly the same. 
Preserve the original lighting, shadows, and perspective. 
Do not alter anything else. 
Output a photorealistic product image.
```

### 6.3 局部组件替换（如灯泡）

**输入**：原图 + mask（透明区域=灯泡区域）
**Prompt**：

```text
Replace only the light bulb with {bulb_description}. 
Match the original socket position, scale, perspective, and lighting. 
Keep the lampshade, metal frame, cable, background, and all text and logo 
completely unchanged. 
Do not alter anything else. 
Output a photorealistic product image.
```

### 6.4 文字替换

**输入**：原图 + mask（透明区域=目标文字块）
**Prompt 模板**：

```text
Replace the text "{original}" located in the {position} corner with "{replace}". 
Match the original font style, weight, color, size, perspective, and shadow exactly. 
The new text must be perfectly spelled and aligned. 
Do not alter any other text, graphics, the {subject}, or the background. 
Output a photorealistic e-commerce product image.
```

### 6.5 Logo 替换

**输入**：原图 + `our_logo.png`（作为第二张图）+ mask（透明区域=旧 Logo 区域）
**Prompt**：

```text
Remove the existing logo in the {position} area. 
Replace it with the logo from Image 2: the {brand} wordmark, clean sans-serif, 
{brand_color}. 
Scale it to fit the same bounding box, maintain its original aspect ratio, 
and preserve the background texture and lighting in that area. 
Do not change anything else in the image. 
Output a photorealistic e-commerce product image.
```

## 八、编辑策略：串行 vs 合并

**默认策略：单指令串行。**

每一轮编辑只改一个区域，每一步的输出作为下一步的输入。每一步 prompt 都重新声明完整的锁定清单。

**允许合并的情况**：

- 编辑之间**空间不重叠**：例如"文字替换 + Logo 替换"（两个区域不交叉）
- 编辑类型**高度同质**：例如 5 张图都只需要"统一把背景换成白色"
- **快速试稿阶段**：用 Flare 模型低成本批量试跑

**不允许合并的情况**：

- 涉及**同一区域**或存在语义依赖的编辑：例如"换背景 + 调主体颜色"（都涉及主体光影）
- 需要**稳定、可追溯**的批量产出

**分层策略**：

- 第一层：空间不重叠的编辑 → 可以合并
- 第二层：涉及同一区域或存在语义依赖 → 必须拆开
- 第三层：用 Flare 做批量草稿，用 Sunburst 做最终精修

## 九、后端 API 设计

### 9.1 路由一览

**POST /api/upload**
- 上传参考图片（支持多文件）
- 返回：`{file_id, filename, url, width, height}`

**POST /api/analyze**
- 请求：`{file_ids: [...]}`
- 对每张图跑 OCR 和 Logo 检测
- 返回：每张图的 text_blocks、logo_blocks、缩略图 URL

**POST /api/generate/batch**
- 请求体：
```json
{
  "source_ids": ["id1", "id2", "id3", "id4", "id5"],
  "edit_rules": {
    "text_replace_enabled": true,
    "logo_replace_enabled": true,
    "background_replace_enabled": true,
    "background_prompt": "modern minimalist living room...",
    "shade_color_enabled": true,
    "shade_color": "#B8B0A8",
    "quality": "high",
    "size": "1024x1024",
    "strategy": "serial"
  },
  "per_source_overrides": {
    "ref_03": {
      "text_blocks": [
        {"id": "T1", "replace": "LUMOS 新品首发", "enabled": true},
        {"id": "T8", "enabled": false}
      ]
    }
  }
}
```
- 返回：`{task_id, status: "queued", total: 5}`

**GET /api/task/{task_id}**
- 返回任务状态、每张子图的进度、完成后的输出图 URL 列表
- 支持 SSE 推送：`GET /api/task/{task_id}/stream`

**POST /api/task/{task_id}/retry**
- 请求：`{job_id: "..."}` 重试单个 Job
- 请求：`{source_id: "..."}` 重试整张图

**POST /api/task/{task_id}/job/{job_id}/edit**
- 修改单步的 prompt 后重新执行

**POST /api/composite**
- 请求体：
```json
{
  "image_ids": ["out_1", "out_2", "out_3", "out_4", "out_5"],
  "gap": 0,
  "background_color": "#FFFFFF",
  "padding_top": 0,
  "padding_bottom": 0,
  "output_width": 750
}
```
- 返回：拼接后的长图 URL

**GET /api/files/{file_id}**
- 返回图片文件

**GET /api/tasks**
- 任务历史列表

### 9.2 状态机

**单张图状态**：`PENDING → PROCESSING → DONE / FAILED`
**批次状态**：`QUEUED → RUNNING → COMPLETED / PARTIAL_FAILED / FAILED`

### 9.3 并发控制

- 使用 `asyncio.Semaphore(3)` 限制同时进行的 API 调用数
- 每个 Job 独立重试，最多 2 次
- 单个 Job 失败不影响其他 Job
- 整体若存在失败，标记为 `PARTIAL_FAILED`
- 每个任务保存完整的输入快照
- 任务状态持久化到 SQLite，支持服务重启后恢复

## 十、前端交互流程

### 10.1 页面结构

**路由**：

- `/` → 工作台主页（上传 + 编辑规则配置 + 提交）
- `/tasks` → 任务列表
- `/tasks/:id` → 任务详情（结果对比、单张重试）
- `/composite` → 长图拼接编辑器

### 10.2 完整操作剧本

```text
1. 打开 localhost:5173
2. 拖入 5 张参考图
3. 系统自动 OCR，原图上叠加编号标注框（T1、T2...；L1、L2...）
4. 右侧表格展示每处文字的 ID、位置、原文、替换为
5. 用户填写品牌 LUMOS、新文案、上传 Logo
6. 开启文字/Logo/背景/主体调整，填写参数
7. 表格与图片标注框双向联动高亮
8. 点击"开始批量生成"
9. 确认框显示"将处理 5 张图，预计消耗 N 次 API 调用"
10. 进入任务详情页，实时进度条
11. 逐张对比审核（左右滑块对比）
12. 不满意的点"重试单步"或"微调 Prompt"
13. 5 张全部通过，点击"加入长图拼接"
14. 长图拼接页拖拽排序，设置 750px 宽、间距 0、白底
15. 点击"生成长图"，预览，下载
```

## 十二、分阶段开发指令

请按以下顺序逐步实现，每完成一个阶段后停下来让我确认。

### 第一阶段：后端核心能力

实现单张图的编辑流程：上传图片 → 生成简单矩形 mask → 调用 `gpt-image-2.5-sunburst` edits 接口 → 保存输出。用一张测试图验证 API 调用正常。

**交付物**：`POST /api/upload` + 一个 CLI 脚本，跑通单张图编辑。

### 第二阶段：OCR 与多文字块

接入 PaddleOCR，实现 `POST /api/analyze`，返回每个文字块的 ID、bbox、位置、原文。生成每块的独立 mask。

**交付物**：`POST /api/analyze` + mask 文件目录。

### 第三阶段：批量处理

把单张流程封装为异步任务，支持 5 张图并发处理（并发数 3），实现任务状态查询接口。每张图按文字块列表串行调用。

**交付物**：`POST /api/generate/batch` + `GET /api/task/{task_id}`。

### 第四阶段：Prompt 模板化

实现 `prompt_builder.py`，从 config 渲染出每种编辑类型的 prompt。文字替换 prompt 必须包含位置描述和原文引用。

**交付物**：5 种编辑类型的 prompt 模板 + 参数化配置。

### 第五阶段：长图拼接

用 Pillow 实现纵向拼接接口，支持间距、背景色、输出宽度、顶部/底部留白。

**交付物**：`POST /api/composite`。

### 第六阶段：前端工作台

搭建 React + Vite + Antd 项目，实现上传、原图编号标注框、文字块表格、编辑规则配置、任务提交。

**交付物**：`/` 页面，运行在 `localhost:5173`。

### 第七阶段：任务详情与长图拼接页

实现任务详情页（实时进度、结果对比、单张重试、微调）和长图拼接编辑器。

**交付物**：`/tasks/:id` + `/composite` 页面。

### 第八阶段：联调与优化

配置 Vite proxy、CORS，端到端测试完整流程。加入 SSE 实时推送、任务持久化、历史任务页。

**交付物**：完整可运行的端到端流程。

## 十三、关键实现细节提醒

### 13.1 Mask 生成

- 文字替换：用 PaddleOCR 检测文字块 → 向外扩展 5-8 像素 padding → 在黑色画布上绘制白色矩形 → 保存为带 alpha 的 PNG
- Logo 替换：由用户指定位置或前端手动框选
- 背景替换：用 rembg 生成主体分割 mask，透明区域=原背景
- 主体局部更换：由用户在前端框选或输入区域描述

### 13.2 位置映射

从 bbox 中心坐标归一化到 0-1，映射到九宫格：

```python
def bbox_to_position(bbox, img_w, img_h):
    x1, y1, x2, y2 = bbox
    cx = (x1 + x2) / 2 / img_w
    cy = (y1 + y2) / 2 / img_h
    col = "left" if cx < 0.33 else "right" if cx > 0.67 else "center"
    row = "top" if cy < 0.33 else "bottom" if cy > 0.67 else "middle"
    return f"{row}-{col}" if not (row == "middle" and col == "center") else "center"
```

### 13.3 输入快照

每个 Job 必须保存完整输入快照：原图哈希、prompt、mask 路径、模型参数、API 返回的 task_id、耗时、token 消耗。保存为 JSON，便于追溯。

### 13.4 幂等重试

每个 Job 有唯一 ID，重试时不重复扣费。已成功完成的 Job 不会重新调用 API。

### 13.5 前端进度推送

优先用 SSE（`GET /api/task/{task_id}/stream`）。起步方案可以是前端每 3 秒轮询一次 `GET /api/task/{task_id}`。

### 13.6 `input_fidelity` 参数

OpenAI SDK 支持 `input_fidelity` 参数（`"high"` 或 `"low"`）。电商改图建议默认 `"high"`。但需要在代码里做异常处理——如果 API 返回错误，自动降级为不传该参数重试。

### 13.7 质量衰减提醒

在 `input_fidelity: "high"` 模式下，3-5 轮编辑后图像可能出现颗粒感或去饱和。建议每 N 次编辑后重新插入原始参考图。在工作流里，可以把"背景 → 灯罩 → 灯泡"作为一组，从原始图重跑一遍，而不是在已经改了 3 步的图上继续改。
