# 线上部署文档

本文档按当前项目和 2 核 2G 云服务器编写。线上使用 Docker Compose，公网通过云服务器的公网 IP 或域名访问，不使用 NATAPP；OCR 功能不作为线上用户功能开放。

## 一、上线前准备

准备 Linux 云服务器、域名（可选）、Docker Engine 和 Compose Plugin，以及 OpenAI 兼容接口的 API Key 和 Base URL。安全组开放 `22`、`80`、`443`，应用端口 `8080` 只允许本机访问。

建议给 2G 服务器配置 2–4GB swap。

## 二、上传项目

```bash
git clone <仓库地址> /opt/aigc-agent
cd /opt/aigc-agent
```

不要上传 `.env`、`secrets/` 和本地测试账号；在服务器单独创建 `.env`。

## 三、配置环境变量

```bash
cp .env.example .env
nano .env
```

至少填写并按 2G 机器限制并发：

```dotenv
OPENAI_API_KEY=你的接口密钥
OPENAI_BASE_URL=https://你的兼容接口/v1
MODEL_EDIT=gpt-image-2.5-sunburst
MODEL_DRAFT=gpt-image-2.5-flare
MAX_CONCURRENCY=2
USER_CONCURRENCY=1
MEMBER_CONCURRENCY=2
REQUEST_TIMEOUT=300
JOB_TIMEOUT=360
MAX_RETRIES=2
DATABASE_URL=
COOKIE_SECURE=false
APP_ENV=production
ALIPAY_MOCK=true
SMS_MODE=disabled
```

正式配置 HTTPS 后，将 `COOKIE_SECURE` 改为 `true`，并把支付回调地址改成 HTTPS 域名。`.env` 不要提交 Git。

## 四、启动服务

```bash
docker compose up --build -d
docker compose ps
docker compose logs -f --tail=100 backend
curl http://127.0.0.1:8080/api/health
```

浏览器可先访问 `http://服务器公网IP:8080` 验收。生产环境建议用 Nginx 或云负载均衡把域名转发到 `127.0.0.1:8080` 并启用 HTTPS；不要暴露 8000 端口。

## 五、上线验收

1. 打开首页并登录测试账号。
2. 上传图片，确认任务创建、轮询、生成和下载正常。
3. 用第二个账号确认数据隔离。
4. 检查后端日志，没有 OOM、数据库锁或 API 超时。
5. OCR 不在前端菜单和普通用户流程开放；2G 机器不要并发启用 OCR、抠图等额外模型功能。

## 六、日常运维

```bash
docker compose ps
docker stats
docker compose logs --tail=200 backend
```

发布新版本：

```bash
git pull
docker compose up --build -d
```

停止服务：

```bash
docker compose stop
```

不要使用 `docker compose down -v`，否则会删除任务、上传文件和生成结果所在的 volumes。

## 七、备份与扩容

至少每天备份 `backend-data` 和 `backend-media` volumes 到另一台机器或对象存储，并定期检查：

```bash
df -h
docker system df
```

2 核 2G 可以承载几十个低频用户。若出现 OOM、任务失败或内存长期超过 80%，先降低 `MAX_CONCURRENCY`，再升级到 4GB 内存。
