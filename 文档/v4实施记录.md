## SQLite 迁移演练

先让任务完成或明确取消并处理至终态，再停止后端。以下命令在项目根目录执行，使用项目 Python 环境。不要对正在运行的实例执行维护命令。命令不会自动终止任务，也不会修改实际现存库，除非显式指向它。

```powershell
python -m backend.manage --database backend/data/tasks.db --media backend/media backup backups/pre-v4
python -m backend.manage --database staging/tasks.db --media staging/media restore backups/pre-v4
python -m backend.manage --database staging/tasks.db migrate
python -m backend.manage --database staging/tasks.db init-admin --username admin
python -m backend.manage --database staging/tasks.db --media staging/media validate
```

备份记录原媒体根目录；恢复时会将 files、jobs 的输入/输出/Mask 路径及任务规则中位于该根目录内的路径改为新媒体目录。跨操作系统迁移建议保持容器内 `/app/backend/media` 路径，根目录之外的引用须单独处理。校验命令返回缺失文件清单，出现缺失时不可上线。

恢复命令拒绝覆盖已有数据库与媒体。备份包括敏感渠道配置，应限制备份目录权限。发生真实充值后，不能直接恢复旧库抹掉账目。

## PostgreSQL

安装更新后的 `backend/requirements.txt`，设置强随机 `POSTGRES_PASSWORD`（URI 特殊字符须编码），使用：

```powershell
docker compose -f docker-compose.yml -f docker-compose.postgres.yml up -d postgres
```

停止后端的状态下，在 backend 容器中运行维护命令（首次可用 `docker compose ... run --rm backend python -m backend.manage ...`）。空库执行 `migrate`、`init-admin`；导入历史库执行 `import-sqlite /app/backend/data/tasks.db`，源 SQLite 必须已在演练副本上完成迁移及超管初始化。导入目标必须为空或与源库内容完全相同。之后执行 `validate`，确认后启动单个后端进程。不要先启动后端再导入，以免自动播种渠道造成冲突。

PostgreSQL 使用 `pg_dump` / `pg_restore`，媒体另行备份。生产 HTTPS 设置 `COOKIE_SECURE=true`，并配置准确的 `FRONTEND_ORIGINS`。

## P1 账号与隔离

迁移 3 新增验证码与登录限流记录，以及按所有者唯一的分类显示名称。注册用户名统一为 3–24 位中文、字母、数字、下划线，不能为纯数字；密码 8–64 位。手机号暂支持中国大陆号码。

- `/api/auth/sms` 支持 `register`、`reset` 两种用途，验证码 5 分钟有效、最多 5 次验证、单次使用；同一手机号发送间隔 60 秒、每天最多 10 次，同一来源 IP 每小时最多 20 次。密码登录按账号和来源分别限流。不会信任客户端提供的代理 IP 头。
- 验证码摘要使用数据库中的随机 HMAC 密钥，原码不存数据库、不返回 API、不写日志。重置密码撤销全部旧会话；禁用后撤销会话，重新启用不恢复旧会话。
- 任务详情、取消、下载、源图、输出文件名、Mask、缩略图、OCR、拼接及模板分类均校验归属；批量引用先逐项检查再操作。普通用户无法访问渠道、用户管理及未计费生图/重试入口；私有资源越权返回 404。
- 普通用户首页统计仅自己的任务，渠道与平台预估成本不展示；任务/OCR 错误不暴露内部路径和上游原始错误。公共模板只由管理员发布，用户可以读取公共模板并维护自己的私有模板。
- 新增 `/register`、`/forgot-password`；登录页面支持用户名/手机号，登录守卫与角色导航生效。普通用户可上传、识别、拼接、维护模板；生图按钮暂不可用并说明未扣积分。
- 管理员 `GET /api/admin/users` 与 `POST /api/admin/users/{id}/status` 支持用户启停，要求原因并写审计。当前尚无用户管理页面。

### 短信配置

默认 `SMS_MODE=disabled`，发送返回明确的 503。真实服务通过 `SMS_MODE=http`、`SMS_HTTP_URL`（HTTPS）、`SMS_HTTP_TOKEN` 对接自有服务商网关：POST JSON `phone/purpose/code/request_id`，接收成功返回 HTTP 200 和 `{"accepted":true}`。不自动重试发送；当前未配置或验收真实供应商。

本地开发可设置 `APP_ENV=development`、`SMS_MODE=test`、`SMS_TEST_OUTBOX=绝对路径`，验证码写入该目录的独立 JSON 文件。收件目录必须与媒体目录分离，不能公开映射；生产环境不接受测试发送模式。浏览器通过正常注册流程发送后，开发者在本地收件目录查看验证码。
